The Context Engineering Pipeline

Most tools dump logs into an LLM. kairos engineers the context through 8 stages before the model sees a single token.

1

Resolve

Service catalog + dependency graph → which sources to query

2

Classify

Infer alert type (error_rate / latency / availability) from title

3

Fetch

Parallel multi-source: NR, Datadog, Loki, HTTP, files. Track quality.

4

Compress

Dedup, pattern normalize, repetition collapse. [x47] connection refused

5

Score

Keyword + alert-type boosts. Dependency lines at 70% priority.

6

Budget

Token-aware selection. 10K budget. Every token earns its place.

7

Prompt

Structured with triple repetition. Situation → quality → evidence → task.

8

Assess

Quality report: which sources succeeded, failed, or returned empty.

Architecture

Triggers (Inbound)

POST /webhook/newrelic

New Relic alert notifications. Auto-extracts service, severity, condition.

POST /webhook/pagerduty

PagerDuty V3 webhooks with HMAC-SHA256 signature validation.

POST /slack/command

/kairos investigate <service> — on-demand triage from Slack.

Source Connectors

6 built-in connectors

New Relic (NerdGraph NRQL), Datadog (Logs API v2), Grafana Loki (query_range), Generic HTTP/REST, File (glob patterns). Extensible via Source protocol.

Intelligence Layer

Service Catalog

Services declare dependencies, owners, tiers, and source mappings. When payment-service alerts, kairos also pulls logs from stripe-gateway and postgres.

Alert-Type Scoring

Error rate → boost stack traces. Latency → boost timeouts. Availability → boost OOM/SIGKILL. Scoring adapts to what the alert is about.

Quality Assessment

Reports what's missing, not just what's found. "Datadog returned 403." "No ERROR lines despite error alert." Claude factors gaps into confidence.

Level 1 Compression

Dedup identical lines [x47]. Normalize timestamps/UUIDs/IPs. Collapse repetitive patterns. 173 lines → 61 (65% reduction).

Context Engineering Principles

Based on research from Stanford, IBM Research, Google Research, and Anthropic. Every design decision in kairos maps to an empirically validated principle.

🔍

Selection (WSCI)

Service catalog resolves which sources to query. Don't fetch everything — fetch what's relevant to this service and its dependencies.

🗜

Compression (WSCI)

500 compressed lines > 5,000 raw lines. Dedup, pattern normalization, repetition collapse. Zero LLM cost.

🎯

Scoring

Alert-type-aware relevance ranking. ERROR +10, service mention +5, plus alert-specific boosts. Token budget enforced.

⚠

Quality Assessment

The model needs to know its blind spots. Report failed sources, empty results, and missing data types so it can calibrate confidence.

📋

Prompt Structure

Triple repetition (Leviathan et al., 2025): key context at start, mid-log anchor, and end. 47/70 accuracy wins, 0 losses.

💰

Model Tier Arbitrage

Engineered context + Haiku matches raw dump + Opus on structured tasks. 24x cost reduction. ACE (ICLR 2026) validates this.

Research Foundation

Lost in the Middle

Liu et al. · Stanford · 2023

U-shaped attention curve. 20+ documents in context drops performance below no-context baseline. More data = worse results.

Needle in the Haystack

Nelson et al. · IBM Research · 2024

Simple fact retrieval breaks down as context length increases. Longer window = more noise = worse recall.

Prompt Repetition

Leviathan et al. · Google Research · 2025

Repeating the query improves accuracy in 47/70 tests with 0 regressions. Prompt structure is functional, not cosmetic.

AI vs Human Code Quality

CodeRabbit · 2026

AI output has 1.7x more issues. "Input quality directly correlates with output reliability." Context engineering is the guardrail.

5-Minute Quickstart

# Install
pip install .

# Interactive setup
kairos-agent setup

# Test locally
kairos-agent test --config kairos.yaml --service your-service

# Start with public tunnel (receives webhooks from NR/Slack)
export ANTHROPIC_API_KEY="sk-ant-..."
kairos-agent --config kairos.yaml --tunnel

The tunnel prints webhook URLs. Copy them into New Relic and Slack. Done.

Configuration

Service Catalog

services:
  payment-service:
    depends_on: [stripe-gateway, postgres]
    owners: [payments-team]
    sources: [newrelic-prod]
    tier: critical

  stripe-gateway:
    sources: [newrelic-prod]
    tier: critical

Source Connectors

log_sources:
  - name: newrelic-prod
    type: newrelic
    credentials:
      api_key: "${NEW_RELIC_API_KEY}"
    options:
      account_id: "1234567"
      region: "eu"
      query: "SELECT timestamp, message, level
              FROM Log
              WHERE service = '{service_name}'"
