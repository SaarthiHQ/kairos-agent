Context Engineering Landscape

What exists, what each does, and where Saarthi's framework fits.

1. Frameworks and Orchestrators

LangChain / LangGraph

75K+ GitHub stars · Most widely adopted LLM framework
Chains of LLM calls with memory modules, RAG pipelines, agent workflows. LangGraph adds stateful orchestration with checkpointing.

Strength: Broad ecosystem, most tutorials target it.

Weakness: Higher latency (~10ms vs ~6ms). Generic — no domain-specific intelligence.

For Saarthi: A tool, not a competitor. Saarthi's framework could use LangChain components internally, but the intelligence (scoring, compression, quality assessment) is what LangChain doesn't provide.

LlamaIndex

Data-first framework · Ingestion, chunking, indexing, retrieval
Designed for connecting LLMs to data. Hierarchical indexing, semantic chunking, re-ranking, context window assembly.

Strength: Best-in-class retrieval quality. Lower latency. Handles messy documents well.

Weakness: Stateless by default. Retrieval-focused, not orchestration-focused.

For Saarthi: LlamaIndex's retrieval could be a source connector in the Saarthi framework, especially for medical document search. Complementary, not competitive.

Google ADK (Agent Development Kit)

Open-source · Multi-agent-native · Tiered context architecture
Three-tier storage: Session (conversation), Memory (long-term), Artifacts (files/data). Named, ordered "processors" transform context. Strict scoping — each agent sees minimum required context.

Strength: Most architecturally mature approach to context isolation. Multi-agent by design.

Weakness: Google ecosystem bias. Less adoption than LangChain.

For Saarthi: The closest to what we need. Tiered context (Session/Memory/Artifacts) maps to our pipeline. The "processors" concept maps to our compression/scoring. Study deeply.

Model Context Protocol (MCP)

Linux Foundation · 97M+ monthly SDK downloads · Universal standard
Standardizes how tools are defined, invoked, and how results flow into context. Just-in-time instruction injection for scaling beyond 50+ tools.

Strength: Universal adoption (Anthropic, OpenAI, Google, Microsoft). 75+ official connectors.

Weakness: Protocol, not a framework. Handles connectivity, not scoring or compression.

For Saarthi: Make kairos Sources MCP-compatible for universal tool integration. Future standard for how the framework connects to data.

2. Memory and Persistence

Mem0

arXiv:2504.19413 · Universal memory layer for AI agents
Extracts, consolidates, and retrieves salient information from conversations. Semantic search + recency weighting + graph memory for relationships.

Strength: 91% lower p95 latency. 90% token cost reduction. 26% improvement in LLM-as-a-Judge metric.

Weakness: Conversation-centric. Designed for chatbots, not incident management or clinical decision support.

For Saarthi: Memory extraction + graph relationships directly applicable to incident history and patient history. Consider as dependency for the "Write" operation in WSCI.

3. Research: Self-Improving Context

ACE — Agentic Context Engineering

arXiv:2510.04618 · ICLR 2026 · GitHub
Treats contexts as evolving playbooks. Three components: Generator (produces output), Reflector (analyzes success/failure, extracts lessons), Curator (integrates lessons as incremental updates). "Grow-and-refine" mechanism prevents context collapse.

Strength: +10.6% on agent benchmarks. Matches top-ranked production agents on AppWorld with a smaller model.

Weakness: Academic — not production-ready. Three-component architecture adds complexity.

For Saarthi: The Reflector concept is exactly what kairos needs for v0.4+ (learning from past incidents). After each triage, a Reflector extracts "what worked" and the Curator updates scoring rules. Highly relevant.

4. Production Lessons: Manus AI

Manus — Context Engineering for Production Agents

Blog post · Rebuilt framework 4 times
General-purpose AI agent. Most mature production context engineering documented publicly. ~50 tool calls per task. 100:1 input-to-output token ratio.

Manus's key strategies, ranked by relevance to Saarthi:

KV-Cache
Cache hit rate is the #1 metric. Append-only context, stable prefixes, deterministic serialization. Cached tokens cost 10x less ($0.30 vs $3.00/MTok on Claude). Critical for Saarthi SaaS economics.
Recitation
Agent rewrites a todo.md at each step, pushing goals into recency attention span. Mitigates lost-in-the-middle across ~50 tool calls. Validates our triple prompt repetition approach.
Error keeping
Leave failed actions in context. Seeing its own mistakes helps the model avoid repeating them. Validates our quality assessment (showing gaps, not hiding them).
Mask, don't remove
Don't dynamically add/remove tools (breaks cache). Use logit masking to constrain availability. Relevant when kairos becomes agentic (v0.5).
Filesystem
Treat files as unlimited context. Write data to files, read back on demand. Restorable compression — drop content if URL/path is preserved. Applicable to medical document handling.
Break patterns
Introduce structured variation in serialization to prevent repetitive rhythms. Prevents hallucination during batch operations.

The Gap Saarthi Fills

Every existing framework is either:

  • Generic orchestration (LangChain, LangGraph) — you build context engineering on top
  • Retrieval-focused (LlamaIndex) — great at finding documents, doesn't score or compress domain-specifically
  • Memory-focused (Mem0) — great for conversation history, not for system data or clinical records
  • Research (ACE) — great ideas, not production-ready
  • Single-product (Manus) — deeply optimized for one product, not reusable

Saarthi's framework combines multi-source fetch, domain-specific scoring, domain-specific compression, entity graph awareness, and quality assessment — reusable across domains.

The moat is domain-intelligent context engineering as a reusable framework.

6. What to Adopt from Each

Google ADK

ACE
Generator → Reflector → Curator is the self-improvement loop. Implement for incident history learning.
Mem0
Memory extraction + graph relationships. Use for patient history and incident history persistence.
MCP
